# AI 生成 UI の slop サインと品質ゲート

## 1. 概要

AI が生成した UI には、均質で「いかにも」な型（slop）が現れやすい。Hallmark の設計から、その型を検出可能なサイン（tells）として列挙する方法と、品質チェックを3層のゲートに分ける運用を抽出した。検品のチェックリストとして使える形に整理する。

## 2. 基本概念

- **tells（サイン）**：機械生成らしい見た目の兆候。抽象的な「AI っぽさ」ではなく、個別に指摘・検出できる形で列挙される。
- **Floor（床）**：絶対に出荷しない条件。コントラスト、フォーカス、reduced motion、事実の捏造、壊れたスマホレイアウト。
- **Reflex（反射）**：モデルが陥りがちな既定。理由を記録すれば、ビルドは覆してよい。
- **Finish（仕上げ）**：工芸の細部。納品を止める条件にはしない。
- **仕事（job）から組み立てる**：ページの構成は、来訪者が何をしに来たかで決める。主アクションはカテゴリの定位置に置き、ページはそれで終わる。
- **テーマはマテリアル**：テーマは紙・書体・色・表面・部品・質感の指定であり、中身や順序を決める雛形ではない。

## 3. 詳細解説

Hallmark が lint で検出する tells の例は次のとおりである。

- すべての見出しの上に付く eyebrow（小ラベル）
- 字間を広げた大文字のラベル
- 見出しの中の1語だけ色を変える装飾
- 空の枠だけが並ぶページ、または写真だけのページ
- 画面（ファーストビュー）に収まらないヒーロー
- どのページの最後にもあるメール登録フォーム
- 実際には送信していないのに「ありがとう」と表示するフォーム

これらは実ブラウザでレンダリングして検査される（sloplint --render、8つの幅）。静的なコード走査ではなく、表示された結果を見る点が特徴である。

検証の順序も設計されている。ヒーローは単独で先に作り、ページの残りが存在しない状態で冷静にレビューする。全体ができた後の手直しより、最初の画面の質を先に確定させる。最後は、新鮮な文脈を持つレビュアー（サブエージェント）が決定打を持つ。作った本人の文脈を引き継がない目で見ることで、見慣れによる見落としを避ける。

再設計（redesign）では、変更前のリンク・フィールド・ハンドラ・見出しを記録し、変更後に欠落がないことを機械的に確認する（--kept）。「作り替える」と「欠落させない」をセットにする運用である。

## 4. 仕組み・構造

ゲートの3層は、厳しさと運用が異なる。

| 層 | 対象 | 違反時の扱い |
|---|---|---|
| Floor | コントラスト、フォーカス、reduced motion、捏造、スマホレイアウトの破綻 | 出荷しない |
| Reflex | モデルが陥る既定（tells を含む） | 理由を記録すれば覆せる |
| Finish | 工芸の細部 | 納品を止めない |

## 5. メリット・デメリット

メリットは、「AI っぽさ」という曖昧な不満を、指摘可能な項目に分解できること、ゲートの層分けにより最低ラインと好みを混同せずに済むことである。

デメリットは、tells の列挙が時代とともに陳腐化すること（型が変われば検出項目も変える必要がある）、また実ブラウザ lint の仕組みを用意するコストがかかることである。

## 6. 活用例

- 生成されたページの検品で、eyebrow の有無、見出しの色変え、ヒーローの収まり、末尾フォームの実在（送信されるか）を確認する。
- 自分の制作物の品質基準を Floor／Reflex／Finish に分けて書き、レビューの議論を「床の違反か、好みの問題か」で整理する。
- 再設計の際に、変更前の要素一覧を記録し、欠落チェックを入れる。
