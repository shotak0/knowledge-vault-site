# アニメーションと質感の判断基準

## 1. 概要

インターフェースの「質」は、カーブ・時間・影といった小さな判断の集積で決まる、という Emil Kowalski のスキル集から抽出した判断基準である。エージェント（および人間）が陥りがちな誤選択と、その正解側の既定値を対で整理する。アニメーションは「足す」だけでなく「消す」判断も含む。

## 2. 基本概念

- **イージング（easing）**：アニメーションの加減速カーブ。要素の現れ方・消え方の印象を決める。
- **振り付け（choreography）**：複数要素が動くときの、先行・追随・並行・静止の割り当て。
- **ジェスチャの追随**：ドラッグやスワイプが指に 1:1 で追随し、離した瞬間の速度を引き継ぎ、途中でも掴み直せること。
- **最悪ケースデータ**：長い名前、巨大な件数、空リストなど、UI を壊しにいくための入力（break-ui の考え方）。

## 3. 詳細解説

- **入場は ease-out、ease-in は避ける**。速く始まって滑らかに止まる動きが自然で、ease-in は反応の鈍さとして感じられる。退場は入場より短く、邪魔にならないことが優先される。
- **境界はベタ塗りの線より半透明の影**。線は画面を硬く区切り、影は奥行きとして読める。質感の判断はこうした置き換えの積み重ねである。
- **動きの対象と性能**：フレーム落ちの多くは、アニメーションさせるプロパティの選択と、メインスレッド上での作業に起因する。transform と opacity のような合成しやすいプロパティを優先し、落ちる場合は animation-performance の観点（何がフレームを落としているか）で切り分ける。
- **消す判断**：キーボードショートカットへの動き、全セクションへの一律のフェードイン、ツールチップ群への一律の遅延は、目的のない動きとして削除の対象になる。動きは「気づかせるべき変化」がある場所だけに使う。
- **振り付け**：同時に動く要素には、どれが先行し、どれが追随し、どれが並行し、どれが動かないかを決める。全要素が一斉に動くと、視線の置き場がなくなる。
- **ジェスチャ**：シートやドラッグは指に 1:1 で追随させ、離した速度をアニメーションに引き継ぎ、遷移の途中でも掴み直せるようにする。固定の時間で再生されるだけの動きは「アプリらしく」感じられない。
- **スマホの作法（mobile-native）**：スティッキーになるホバー状態、タップハイライトの閃光、100vh 問題（svh 等の単位で回避）、入力欄の文字サイズ不足による自動ズーム、タップの遅延、セーフエリアへの配慮。これらは小さいが、Web ページとアプリの体感差になる。

## 4. 仕組み・構造

判断は次の順序で適用すると整理しやすい。

1. その変化に動きが要るか（要らなければ消す）。
2. 要るなら、カーブ（入場 ease-out 等）と時間を決める。
3. 複数要素なら振り付けを決める。
4. 性能を確認する（フレーム落ちがないか、対象プロパティは適切か）。
5. 最悪ケースデータで壊れないか試す。

## 5. メリット・デメリット

メリットは、判断基準が具体的で、そのままレビューの指摘やエージェントへの指示に使えることである。小さな誤選択を先回りで潰せる。

デメリットは、基準がアニメーションと質感に寄っており、レイアウトや配色の体系そのものは別途必要であること、また既定値を機械的に当てると文脈に合わない場合があることである（基準は出発点であり、理由がある場合は変えてよい）。

## 6. 活用例

- 生成された UI のレビューで「入場が ease-in になっている」「境界がベタ線で硬い」「全カードにフェードインが付いている」を指摘観点として使う。
- スマホ向けページの仕上げで、入力欄 16px 以上、セーフエリア、タップハイライトを確認する。
- 既存画面の改善監査で、動きの棚卸し（足す場所／消す場所）を先に行う。
