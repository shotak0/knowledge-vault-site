# Hallmark ― AI 生成らしく見せないデザインスキル

## 1. 概要

Nutlope（Together AI 製）による、Claude Code、Codex、Cursor、OpenCode 向けのデザインスキルである。キャッチフレーズは「AI が生成したように見えることを拒む（refuses to look AI-generated）」。50 種類のテーマ（マテリアル）からその案件に合うものを配り、ページを「来訪者の仕事（job）」から組み立て、実ブラウザでの lint によって「機械生成らしいサイン（tells）」を検出してから渡す、という一連の流れをスキル化している。

本稿は 2026-11-17 時点の main（コミット 04977e15）の README をもとに作成した。リポジトリは更新され続けるため、内容は今後変わりうる。

## 2. 要約

- **3層のゲート**：品質チェックは Floor（絶対に出荷しない：コントラスト、フォーカス、reduced motion、事実の捏造、壊れたスマホレイアウト）／Reflex（モデルが陥る既定。理由を記録すれば覆せる）／Finish（仕上げの工芸。納品を止めない）の3層に分かれる。
- **slop のサイン（tells）**：全見出しの上に付く eyebrow（小ラベル）、字間を広げた大文字ラベル、見出しの中の1語だけ色を変える、空の枠だけのページや写真だけのページ、画面に収まらないヒーロー、どのページの最後にもあるメール登録、送信していないのに「ありがとう」と言うフォーム。これらを実ブラウザで lint する。
- **テーマはマテリアル**：50テーマはそれぞれ紙・書体・色・表面・部品・質感の組であり、「計画」ではない。テーマはページの中身や順序を決めないので、同じテーマでもプロンプトが違えば別のページになる。各テーマは最大 8KB の1ファイルで、ビルド時は正確に1つだけ読む。
- **仕事から組み立てる**：予約ページは予約し、店は売り、ニュースレターは購読させる。主アクションはそのカテゴリの定位置に置かれ、ページはそのアクションで終わる。
- **捏造しない**：事前調査（pre-flight）でプロジェクト（フォント、パレット、フレームワーク、ロックされた design.md）を読み、素材（写真、スクリーンショット、実数）を一度だけ尋ねる。何も発明しない。
- **検証の作法**：ヒーローは単独で先に作り、残りが存在しない状態で冷静にレビューする。sloplint を8つの幅で走らせ、最後は新鮮な文脈のサブエージェントがレビューして決定打とする。

## 3. 背景・前提知識

- **AI slop**：AI 生成物にありがちな、均質で「いかにも」な出力の型を指す言葉。本リポジトリでは、その型を tells として列挙し、機械的に検出する対象にしている。
- **テーマ（マテリアル）**：Hallmark におけるテーマは、レイアウトの雛形ではなく素材の指定である。Dusk（銀行の照合）、Cobalt（Webhook API）、Atelier（香水のアトリエ）のように、完成ページの見本写真と組で提示される。
- **写真の扱い**：755点のオープンライセンス写真（Wikimedia Commons 由来、CC0／パブリックドメイン／CC BY／CC BY-SA）から題材に合うものを選び、ページ上にクレジットする。ストックサイト（Unsplash 等）は、AI ツールによる画像選択を規約で禁じているため使わない、と明記されている。

## 4. 詳細解説

ビルドの流れは README の「How a build runs」に4手順で示される。(1) Pre-flight：プロジェクトを読み、素材を一度だけ尋ねる。(2) theme.mjs の deal がプロンプトに合いログをクリアしたテーマを3つ提示し、draw がページの解剖学（anatomy）をその仕事から配る。(3) ヒーローを単独で構築し、レンダリングして冷静にレビューする。(4) sloplint --render が8幅でページを検査し、サブエージェントが新鮮な目でレビューする。各ページは自己完結した HTML/CSS で、冒頭の CSS コメントに「そのページが取った決定」が刻印される。

v2 の目玉は50テーマと Custom モードである。Custom と言うとテーマを外し、計画も部品もパレットのレシピもなく、Floor とゲートと direction.md の短い方向性だけが残る。「そのクライアントだけが持つ1つのアイデアを見つけ、ページ全体をそれで走らせる」ためのモードである。

Redesign と audit も用意される。`/hallmark redesign <path>` は内容と配線を保ったまま体系とレイアウトを作り替える（keep the layout ならリスタイル、polish なら tells の除去のみ）。sloplint --before がリンク・フィールド・ハンドラ・見出しを事前に記録し、--kept はそのどれかが欠けたら redesign を失敗させる。引き渡しは before／after の並列比較である。

影響元として、Impeccable、frontend-design、Open Design、Kami、taste-skill、huashu-design、UI UX Pro Max、Emil Kowalski のスキル群、Web Interface Guidelines が挙げられている。

## 5. 重要なポイント

- 品質ゲートを「絶対」「既定（覆せる）」「仕上げ」の3層に分けることで、硬直化せずに最低ラインを守れる。
- 「AI らしさ」は抽象論ではなく、列挙可能な tells として検出対象にできる。
- テーマをマテリアルとして分離すると、同じテーマでも内容ごとに異なるページが作れる（雛形のコピペにならない）。
- ヒーローを単独で先に検証する、最後は文脈の新しいレビュアーが決める、という検証の順序設計が品質を作る。
- 再設計では「失われた要素がないこと」を機械的に保証する（--kept）。作り替えと欠落防止はセットである。

## 7. 自分なりの考察

以下は AI による考察であり、リポジトリの主張そのものではない。

- Floor／Reflex／Finish の3層は、デザイン以外の品質基準（テストやレビューの基準）にも転用できる考え方である。「理由を記録すれば覆せる既定」という中間層があることで、ルールが形骸化しにくい。
- tells の列挙は、AI に作らせる側の検品チェックリストとしてそのまま使える。特に「全見出しの上の eyebrow」「1語だけ色変え」は、自分の制作物にも出がちな型である。
- テーマを「最大 8KB の1ファイルだけ読む」という制約は、エージェントの文脈消費を抑える設計でもある。必要な文脈だけを配る、という点でハーネス設計の実例になっている。

## 8. 学んだこと

- AI 生成 UI の「らしさ」は、具体的な tells の集合として扱えること。
- 品質ゲートの3層構造（Floor／Reflex／Finish）と、覆す際の記録という運用。
- ページは「仕事」から組み立てる、テーマは中身を決めないマテリアルである、という分離の考え方。
