# How to choose a Library configuration

## 1. 要約

後で読むサービス Readwise Reader の公式ドキュメントで、保存した文書を整理するライブラリの構成（ワークフロー）を3種類から選ぶためのガイドである。

Reader のライブラリは、保存した文書が住む場所であり、その整理の型として Triage（トリアージ）、Shortlist（ショートリスト）、Classic（クラシック）の3つの構成が用意されている。既定は Triage で、Inbox（受信箱）、Later（後で読む）、Archive（アーカイブ）の3つの置き場所で回す。Shortlist は Later、Shortlist、Archive の3つで、「いつか読むかもしれない」大きな山（Later）から、優先度の高いものだけを小さな読みキュー（Shortlist）に引き上げて分ける型である。Classic は Later と Archive の2つだけの、Instapaper や Pocket のような従来型の最も単純な型である。

ガイドの要点は、構成は読み方や作業の進め方に合わせて選ぶもので、固定ではない、という点にある。構成はいつでも切り替えられ、文書は新しいワークフローの適切な置き場所へ自動で移される。移動が発生する変更では、事前に確認のポップアップが出る。自分に合う構成を選ぶことで摩擦が減り、保存した内容に埋もれず、重要なものを見失わずに済む、とガイドは説明している。

## 2. 重要なポイント

- ライブラリ構成は、保存した文書をどの置き場所（ロケーション）の流れで処理するかを決める、ワークフローの型である。Reader には Triage、Shortlist、Classic の3種類がある。
- 既定は Triage で、Inbox → Later → Archive の流れである。新しい文書はすべて Inbox に入り、1件ずつ処理して、削除するか、アーカイブするか、後で読むために Later へ移す。「inbox zero（受信箱を空にする）」型の運用を好む、生産性重視の利用者向けとされている。
- Shortlist は Later → Shortlist → Archive の流れである。新しい文書は Later に入り、Later は「いつか読むかもしれないもの全部」を抱えるアンチライブラリとして働く。そこから優先度の高いものを Shortlist に引き上げ、Shortlist が実際の読みキューになる。たくさん保存するが、一度に集中して読みたいのは選ばれた少しだけ、という読み方に向く。
- Classic は Later → Archive の流れで、置き場所は2つだけである。新しい文書は Later に入り、読み終えたら Archive に移して恒久保存と将来の参照に回す。余分な仕分けの手順を嫌うミニマリスト向けで、Instapaper や Pocket のような従来の後で読むアプリに似ている。
- 構成は永続的な決定ではない。いつでも切り替えられ、文書は新しいワークフローの適切な置き場所へ自動で移される。文書の移動が発生する変更では、確認のポップアップが事前に出る。試しながら自分の読み方に合う形を探すことが勧められている。
- 変更方法は、Web とデスクトップアプリではライブラリ画面のドロップダウンまたはアカウント設定から、モバイルアプリではアカウントタブの設定から行う。
- Triage 構成でも Shortlist の考え方は使える。Reader には既定のビューとして「⭐ Shortlist」が用意されており、どの置き場所にある文書にも shortlist タグを付けて目印にできる（Web とデスクトップではキーボードの S で素早く付けられる）。
- 各構成にはキーボードショートカットが割り当てられている（Inbox は Shift + E、Later は L、Archive は E、Shortlist は S など）。

## 3. 詳細解説

### 3.1 ライブラリ構成とは何か

Reader において、ライブラリは保存したすべての文書が住む場所である。その文書の群れをどう捌くかは人によって異なるため、Reader は整理のワークフローとして3つの構成を用意している。各構成は、文書を仕分けるための主要な置き場所の組み合わせが異なる。

ガイドはまず、構成の変更方法を説明している。Web とデスクトップアプリでは、ライブラリ画面のタイトル横のドロップダウンから「Edit Library locations」を選ぶ方法と、アカウント設定の「Library configuration」から選ぶ方法の2通りがある。モバイルアプリでは、アカウントタブを下にスクロールして「Library configuration」をタップする。文書の移動が発生する変更（たとえば Inbox から Later への移動）では、変更前に確認のポップアップが表示される。

そしてガイドは、この選択は永続的ではないことを強調している。読み方の癖に合うかどうかは、切り替えて試すのが一番の見つけ方だ、という立場である。

### 3.2 Triage（トリアージ型）

流れは Inbox → Later → Archive である。置き場所は Inbox、Later、Archive の3つで、Reader の既定の構成である。

位置づけは、「inbox zero」型のアプローチを好む、生産性重視の利用者向けである。新しい文書はすべて Inbox に着地し、1件ずつ処理する対象として扱われる。処理とは、削除する、アーカイブする、または後で読むために Later へ移す、のいずれかである。

つまり Triage 型は、保存したものすべてに「一度は判断を通す」ことを前提にした型である。キーボードショートカットは、Inbox が Shift + E、Later が L、Archive が E である。

### 3.3 Shortlist（ショートリスト型）

流れは Later → Shortlist → Archive である。置き場所は Later、Shortlist、Archive の3つで、目先の読書の優先度と、一般的な積読の山を分けるための構成である。

新しい文書は Later に入り、Later は「いつか読むかもしれないもの全部」を抱える場所、ガイドの言葉ではアンチライブラリ（anti-library）として働く。そこから優先度の高いものを Shortlist に昇格させ、Shortlist が実際の読みキュー（active reading queue）になる。

この型は、たくさん保存するが、集中して読みたいのは「必ず読む」ものと「読むかもしれない」ものを分けたうえでの少しだけ、という読み手に向く。キーボードショートカットは、Later が L、Shortlist が S、Archive が E である。

なお、ガイドには補足として、Triage 構成を使っているのに Shortlist のビューが見える理由が説明されている。Triage の構造が好きだが「まず確実に読みたいもの」の選別もしたい、という利用者がいるため、Reader には既定のビューとして「⭐ Shortlist」が用意されている。これは置き場所ではなくタグによる目印で、どの構成・どの置き場所の文書にも shortlist タグを付けて横断的に拾える。Web とデスクトップでは、キーボードの S で素早くタグを付けられる。

### 3.4 Classic（クラシック型）

流れは Later → Archive である。置き場所は Later と Archive の2つだけで、最も単純なワークフローである。Instapaper や Pocket のような従来の後で読むアプリに似ており、余分な仕分けの手順を望まないミニマリストに向くとされている。

新しい文書はすべて Later に保存される。読み終えたら Archive に移し、恒久的な保存と将来の参照に回す。キーボードショートカットは、Later が L、Archive が E である。

### 3.5 なぜ構成が大事なのか

ガイドの結びは、ライブラリは個人の知識の空間であり、自分の自然な傾向に合った構成を選ぶことで摩擦が減り、内容の過多（content overload）に埋もれずに済む、という説明である。合った設定は、保存した内容にきちんと向き合うことを容易にし、重要なものが失われないようにする。

そして繰り返しになるが、構成はいつでも切り替えられ、文書は新しいワークフローの適切な置き場所へ自動で移される。試して見つけることが勧められている。

## 4. 重要な用語

- **ライブラリ構成（Library configuration）**：保存した文書をどの置き場所の流れで処理するかを決める、ワークフローの型。Triage、Shortlist、Classic の3種類がある。
- **Inbox（受信箱）**：Triage 型で、新しい文書が最初に着地する置き場所。1件ずつ処理して捌く前提の場所である。
- **Later（後で読む）**：後で読む文書の置き場所。Triage 型では処理を経て移される先、Shortlist 型と Classic 型では新しい文書の着地先である。
- **Archive（アーカイブ）**：読み終えた文書の恒久保存の置き場所。どの構成にも共通する終点である。
- **Shortlist（ショートリスト）**：Shortlist 型で、Later の山から優先度の高いものだけを引き上げた、小さな読みキューの置き場所。Triage 型ではタグによる既定ビューとしても提供される。
- **アンチライブラリ（anti-library）**：Shortlist 型の Later の位置づけを表すガイドの言葉。「いつか読むかもしれないもの全部」を抱える、未読の山そのものを指す。
- **トリアージ**：もともとは医療で治療の優先順位を付ける考え方。ここでは、入ってきた文書を1件ずつ判断して行き先を決める処理の型を指す。

## 5. 前提知識

- Readwise Reader が、記事や文書を保存して後で読むためのサービスであることを知っていると読みやすい。
- Inbox、Later、Archive のような「置き場所で状態を表す」整理法の考え方に触れたことがあると、各構成の違いが掴みやすい。

## 7. AIによる考察

※この節は AI による考察であり、元ドキュメントの内容ではない。

3つの構成の違いは、突き詰めると「保存したものすべてに判断を通すかどうか」と「読む前の選別をどこでやるか」の2点に集約できるように思う。Triage は入口で全件に判断を通す型で、山が小さいうちは気持ちよく回るが、保存量が判断量を超えると Inbox 自体が新しい山になる。Shortlist はその破綻を見越した型で、山（Later）は山として認めたうえで、読む直前の選別だけを小さく保つ。Classic は、仕分け自体を最小化し、検索や再訪に委ねる型である。

面白いのは、Shortlist の考え方がタグによる既定ビューとして Triage の中にも用意されている点である。置き場所（構造）としては排他的な3択でありながら、「優先の目印」という部品は構成を越えて使える。構造で分けるか、目印で分けるかは、別の設計判断だということだと思う。

また、「構成はいつでも変えられ、文書は自動で移る」という設計は、選択のコストを下げている。整理法の選択は、間違えると移行が面倒で固定化しがちだが、自動移行があることで「試して合わなければ戻す」が現実になる。整理の型そのものより、型を変えられることのほうが、長く使う道具では効いてくるのかもしれない。
