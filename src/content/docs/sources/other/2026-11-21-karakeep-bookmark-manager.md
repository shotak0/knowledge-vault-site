# Karakeep - The Bookmark Everything App

## 1. 要約

Karakeep は、リンク、メモ、画像、PDF を何でも保存できるオープンソースのブックマーク管理アプリの公式サイトである。キャッチフレーズは「The Bookmark Everything App」で、データを貯め込む人（data hoarders）に向けて作られたと自称している。GitHub のスターは30,000を超え、コントリビューターは150人を超える。

中心の考え方は、保存したあとの整理を人にやらせないことである。リンクを保存すると、タイトル、説明、画像を自動で取得し、AI が自動でタグ付けと要約を行い、全文検索と意味による検索（セマンティック検索）の両方で再発見できるようにする。ページ全体のアーカイブ保存により、リンク切れで中身が失われることも防ぐ。画像やスクリーンショットの中の文字は OCR で検索可能になる。

加えて、条件とアクションで自動化ルールを作る機能、RSS フィードを購読すると新着記事を毎時チェックして自動保存する機能、リストを他の人と共有して一緒にキュレーションする機能がある。AI アシスタントとの連携も前面に出ており、公式の MCP サーバー、CLI、権限を絞れる API キー、Markdown で内容を返す API が用意され、エージェントが代わりに検索や保存を行える設計になっている。

提供形態は、クラウド版（無料で試せる）と、Docker で自分のサーバーに立てるセルフホスト版の両方である。オープンソースであり、自分のデータの管理権を自分で持てることが明記されている。価格は公式サイトの記載では0ドル（無料）である。

## 2. 重要なポイント

- Karakeep は、リンク、メモ、画像、PDF を1か所に保存するブックマーク管理アプリで、オープンソースかつセルフホスト可能（Docker）である。クラウド版もあり、無料で試せる。
- 保存時に、タイトル、説明、画像を自動で取得し、文脈（コンテキスト）が失われないようにする。ページ全体のアーカイブも保存するため、リンク切れ（link rot）で中身が消えることを防げる。
- 整理は AI が担う。保存したブックマークには AI が自動でタグ付けと分類を行い、AI 生成の要約も付く。保存した瞬間に整理が終わる、というのが公式サイトの打ち出しである。
- 検索は3モードある。保存したものすべての高速な全文検索、キーワードと意味を組み合わせたハイブリッド検索、言葉ではなく意味で探すセマンティック検索である。「どう覚えているか」で探せることが売りになっている。
- 画像やスクリーンショットの中の文字は OCR で読み取られ、検索の対象になる。
- 読む体験も持っている。記事は広告などのないリーダービューで読め、文章へのハイライトを付けて整理でき、モバイルアプリではオフラインでも読める。
- 自動化ルールを作れる。新しいブックマークの追加をきっかけに、URL のパターンや内容の条件で、タグ付けやリストへの振り分けを自動で行う（例：URL に amazon.com を含むものに Shopping タグを付けて Wishlist リストに入れる）。
- RSS フィードを購読すると、新着記事が毎時チェックされて自動で保存され、タグ付けと検索の対象になる。逆に、任意のリストを RSS フィードとして公開することもできる。
- リストは他の人と共有できる。編集者や閲覧者として招待し、旅行計画、読書会、チームの読み物リストなどを同じコレクションで回せる。
- AI アシスタント連携が公式に用意されている。自然な会話で AI に検索・保存・整理を教えるための Agentic skills、公式の MCP サーバーと CLI、スコープごとに権限（アクセスなし、読み取りのみ、読み書き）を絞れる API キー、保存したページを綺麗な Markdown で返す API である。エージェントが利用者の代わりに検索し保存する使い方を想定している。
- 規模の指標として、GitHub スター30,000以上、コントリビューター150人以上が公式サイトに掲げられている。

## 3. 詳細解説

### 3.1 保存：何でも1か所に

Karakeep の入口は、リンク、メモ、画像、PDF をどのデバイスからでも保存できることである。リンクは1クリックで保存でき、保存時にタイトル、説明、画像が自動で取得されるため、あとから見ても「何のリンクだったか」が失われない。

もう一つの特徴は、ページ全体のアーカイブを残すことである。ブックマークした先のページが消えたり書き換わったりするリンク切れ（link rot）への備えで、保存した時点の中身そのものを手元に残す。

### 3.2 整理：AI に任せる

公式サイトの打ち出しは明確で、「整理に時間をかけるのをやめて、保存するだけにし、あとは AI に任せよう」というものである。保存したブックマークには、AI が自動でタグとカテゴリを付け、要約も生成する。整理は保存した瞬間に起きる（instant organization）とされている。

タグ付けの例として、日本旅行の記事に Travel、Japan、Planning、Itinerary、Budget Travel などのタグが並ぶ様子が、公式サイトの画面例に示されている。

### 3.3 検索：覚え方で探す

探す側の仕組みは3層ある。保存したものすべてを対象とする高速な全文検索。検索バーで切り替えられるキーワード検索、ハイブリッド検索、セマンティック検索の各モード。そして画像やスクリーンショット内の文字を対象にする OCR 検索である。

公式サイトは「言葉ではなく意味で探せる」ことを強調しており、たとえばパスタのレシピを「カリカリのガーリックが乗ったあのパスタのレシピ」という覚え方で探す例が示されている。正確な語句を思い出せなくても、意味の近さで引ける、という設計である。

### 3.4 読む：リーダービューとハイライト

保存した記事は、余分な要素のないリーダービューで読める。読んでいる文章にはハイライトを付けられ、ハイライトは整理された形で参照できる。モバイルアプリではオフラインで読むこともできる。

### 3.5 自動化：ルールと RSS

自動化は2系統ある。1つは自動化ルールで、「ブックマークが追加されたとき」をきっかけに、URL パターンや内容の条件に合うものへ、タグ付けやリストへの追加といったアクションを自動で実行する。公式サイトの例では、URL に amazon.com を含む保存に Shopping タグを付け、Wishlist リストに入れるルールが示されている。

もう1つは RSS フィードの購読で、ブログやニュースサイトを登録すると、毎時チェックされて新着記事が自動で保存され、タグ付けと検索の対象になる。逆向きに、任意のリストを RSS フィードとして公開することもできる。

### 3.6 共有：リストを一緒に育てる

リスト単位で他の人を招待でき、編集者（editor）と閲覧者（viewer）の役割がある。旅行の計画、読書会、チームの読み物リストなど、同じコレクションを複数人で見る使い方を想定している。

### 3.7 AI アシスタントとの連携

公式サイトは「LLM-READY」という節を設け、AI アシスタントとの連携を前面に出している。用意されているのは次の4つである。

- **Agentic skills**：AI アシスタントに、自然な会話を通じて検索、保存、整理のやり方を教える仕組み。
- **MCP サーバーと CLI**：公式の MCP サーバーと、スクリプトやエージェント向けのフル機能の CLI。
- **スコープ付き API キー**：スコープごとに、アクセスなし、読み取りのみ、読み書き、の権限を設定できる。
- **Markdown 優先のコンテンツ**：保存したページは、API 経由で綺麗な Markdown として提供される。

つまり Karakeep は、人が画面で操作する道具であると同時に、エージェントが代わりに検索し、保存し、整理するための受け口を持つ道具として設計されている。

### 3.8 提供形態

Karakeep は完全にオープンソースであり、Docker で自分のサーバーに立てて、データの管理権を自分で持ち続けることができる。クラウド版もあり、無料で試してから始めることもできる。公式サイトの追加情報では、価格は0ドルと記載されている。

## 4. 重要な用語

- **Karakeep**：リンク、メモ、画像、PDF を保存し、AI の自動タグ付けと検索で再発見できるようにする、オープンソースのブックマーク管理アプリ。
- **セルフホスト**：サービスを自分のサーバーで運用すること。Karakeep は Docker でセルフホストでき、データの管理権を自分で持てる。
- **リンク切れ（link rot）**：ブックマークした先のページが削除や移転で失われ、中身が見られなくなること。ページ全体のアーカイブ保存がその備えになる。
- **セマンティック検索**：語句の一致ではなく、意味の近さで探す検索。正確な言葉を思い出せない場合でも、覚え方に近い表現で引ける。
- **OCR**：画像の中の文字を読み取ってテキスト化する技術。Karakeep では、画像やスクリーンショットの中の文字も検索対象になる。
- **自動化ルール**：新しいブックマークの追加などをきっかけに、条件に合うものへタグ付けや振り分けを自動で実行する仕組み。
- **MCP サーバー**：AI エージェントが外部の道具やデータに接続するための共通の仕組み（Model Context Protocol）のサーバー。Karakeep は公式の MCP サーバーを提供し、エージェントから検索や保存ができる。
- **スコープ付き API キー**：権限の範囲（スコープ）ごとに、アクセスなし、読み取りのみ、読み書きを設定できる API キー。

## 7. AIによる考察

※この節は AI による考察であり、公式サイトの内容ではない。

Karakeep の設計で目を引くのは、整理のタイミングを「保存した瞬間」に置いていることである。後からまとめて整理する方式は、量が増えると破綻しやすい。保存と同時に AI がタグと要約を付け、全文と意味の両方で検索できるようにしておけば、「整理し直す」という作業そのものが発生しない。Zenn の記事が「毎日の自動分類」で解いた問題を、Karakeep は「保存時の自動分類」で解いている、と対比できる。

もう一つは、エージェント連携を公式の前提にしている点である。MCP サーバー、CLI、スコープ付き API キー、Markdown で返す API という顔ぶれは、「人が画面で使う道具」から「エージェントが代わりに使う道具」への移行を、製品の側が正面から設計している例だと思う。ブックマーク管理のような個人的な道具ほど、この移行の実験場になりやすいのかもしれない。

一方で、AI の自動タグ付けは、タグの語彙が AI 任せになることも意味する。自分の分類体系（たとえば固定のカテゴリやタグの表記ルール）を持っている場合、その体系に AI の出力を寄せられるかどうかが、導入の判断点になるはずである。公式サイトの範囲では、カスタムの自動化ルールで URL や内容に応じたタグ付けは可能とされているが、タグ語彙そのものの統制の仕組みまでは読み取れなかった。
