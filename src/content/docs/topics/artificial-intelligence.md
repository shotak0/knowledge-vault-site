# 人工知能

## 1. 概要

このテーマでは、AIエージェントと批判的思考の関係を、横断的にまとめる。中心となる問いは、AIエージェントに仕事を任せるときに、自分の思考をどう守るか、である。

現時点では、情報源は1件のみである。Addy Osmani による X の長文記事「Critical thinking when agents do the work」（2026-11-03）と、そこから抽出した Knowledge 2件をもとにまとめたものである。情報源が1件のみであるため、複数の情報源の比較はまだできない。情報が追加されたら、このテーマも更新する。

更新履歴：2026-11-10 に、例題Sourceと Knowledge 2件をもとに初版を作成した。

## 2. 基本概念

- **AIエージェント**：指示を受けて自律的に作業を進める AI システム。コードの作成や変更、テストの実行などを行う。
- **批判的思考**：新しい情報に対して、謙虚な好奇心と健全な懐疑心を持って向き合うこと。異なる見方を取り入れ、自分の意見を作る。
- **委譲**：作業を他者に任せること。任せた側は、結果の責任や判断をどこまで残すかを決める必要がある。
- **認知的降伏**：AIの出力がすっかり自分のものになり、確認の必要すら感じなくなる状態。Wharton の Steven Shaw と Gideon Nave による用語である。
- **認知的負債・理解の負債**：AIに頼ることで自分の理解や思考力が少しずつ失われ、積み重なった状態を指す。Jeremy Twei による「理解の負債」や、Margaret-Anne Storey の共有システム理論の考え方とつながる。
- **検証**：出力が正しいか、意図に沿っているか、副作用がないかを確かめる行為。

## 3. 技術・知識の体系

AIエージェントと批判的思考の関係は、次の三つの層で整理できる。

1. **委譲の層**：作業をどこまで任せるか。委譲の度合いは、所有権を残す段階、出力が前提になる段階、確認の必要を感じなくなる段階へと進む。詳しくは [認知的降伏と認知的負債](../knowledge/ai/cognitive-surrender-and-cognitive-debt.md) を参照すること。
2. **検証の層**：任せた結果をどう確かめるか。「検証済み」の定義を事前に決め、検証の手段をエージェントに渡し、実行結果という証拠を確認する。詳しくは [エージェント作業における検証の習慣](../knowledge/ai/verification-for-agent-work.md) を参照すること。
3. **責任の層**：最終的な責任は人に残る。エージェントが作ったものであっても、責任は委譲できない。判断の基準として、保守する人の前で賭けられるかどうかを問う。

この三つの層は、別々のものではなくつながっている。委譲の段階が進むと、検証の負担が増える。検証の仕組みが弱いと、責任を持てる範囲を超えて委譲してしまう。だからこそ、三つの層をまとめて運用する必要がある。

## 4. 重要な論点

- **委譲は「するか・しないか」ではない**。委譲の度合いは段階で進む。どの段階にいるのかに気づく仕組みがないと、確認の必要を感じなくなる段階まで進んでしまう。
- **全体像の常時保持は目指さない**。大規模なコードベースの全体像を常に頭の中に保つことはできない。目指すのは、必要になったときに理解をオンデマンドで再構築できることである。ただし、そのためには「自分が何を持っていないか」を知っている必要がある。
- **検証のボトルネックは「書くこと」から「確かめること」へ移る**。エージェントはコードを書き、テストを作り、実行し、結果を読んで、人が見る前に何度もやり直すことができる。人の役割は、検証の仕組みを作り、その証拠を確認することである。
- **緑のチェックは一つの性質しか示さない**。テストが通ったことは、そのテストで確認した範囲が通ったことであり、すべてが正しいことの証明ではない。
- **監督そのものが逆説をはらむ**。Anthropic の研究による「監督の逆説」では、Claude を監督するにはコーディング技能自体が必要だが、その技能は AI の過剰な使用で衰えるかもしれないと指摘されている。監督する力を保つには、監督される側の技能も保つ必要がある。
